# Dashboard Through Visible Editors

Prepare individual component documents and source definitions when the user
allows JSON. Do not paste a finished page. Inventory native KPI, Chart, Rich
Content, List and Table capabilities before choosing a composition. Maintain a
reading-order map with spans, content heights and intended mobile behavior;
finalize dimensions before keyboard organization and mobile stacking.

## Sources and precedence first

Use real statistics endpoints for aggregate charts and KPIs, not a copied array
of their current responses. Distinguish endpoint group-by/timeseries aggregates,
raw records, metrics, aliases and transformed state paths. Preserve absence and
errors instead of copying fallback reference numbers. Label illustrative gauges,
progress bars and timeline events separately from backend-derived indicators.

A palette chart can carry sample `data`, legacy `config` and `chartDocument`
simultaneously. Inspect the installed precedence before polishing: changing a
remote config alone does not prove that sample data stopped governing the chart.
In the Hero HQ rc.22 exercise, the data editor's valid remote-source save removed
explicit sample `inputs.data`; Save/Reload was required to abandon a stale value
in the live component. Verify the saved absence and the rendered remote groups.
Use actual catalog resources/operations, allow discovery to settle and satisfy
the editor's metric validation. Do not interpret a temporary empty catalog as a
missing API or replace it with local examples.

The exercised advanced alternative connected page-state ChartConfig objects to
the public Chart Config ports and null to Chart Document ports. It reproduced
the reference's request windows, filters, series and styling through existing
contracts. This is not the default recipe when the installed editor suffices:
it leaves the palette document persisted, and re-opening that editor does not
show the effective projected config. Disclose that authoring/round-trip limit.
Never claim an unregistered `data` port exists or force a graph link to it.

## Free JSON still has a normalizer

After Apply JSON inspect the normalized result, Save/Reopen/Reload and the DOM.
Successful parsing is not proof that a property survives or affects the runtime.
An identical config projected through composition can encounter the same child
normalizer; do not recommend that path without demonstrating it.

Concrete rc.22 List evidence: public `PraxisListVirtualScrollConfig` includes
enabled/itemSize/viewportHeight/buffers, but `layout.virtualScroll` object was
removed by the authoring normalizer, including at the List.config runtime entry.
The visual switch preserved boolean true and produced a CDK viewport. With
compact density its defaults were itemSize48 and height400px; that differs from
the reference's64/380. The independent virtualScroll input accepted richer types
but was absent from composition ports. This was `suportado-parcialmente`, tracked
in praxis-ui-angular#599, not a new-contract requirement. Revalidate in later
releases; do not teach the boolean as exact equivalence or repeat the failed
projection. Retain the functional baseline and quantify remaining differences.

## Avoid transition rework

In the rc.22 prepared take, the same13-widget result took522.755s. Source/catalog
work and navigation were interleaved; this is not an isolated HTTP latency.
Do not repeat the workflow's accidental clicks as required product steps.

- Open a panel once, then observe its named dialog and intended controls before
  selecting a section. A short locator timeout does not prove opening failed:
  inspect for a late panel before activating its launcher again.
- Confirm the selected tab/panel after a navigation change. Controls may already
  exist in outgoing or hidden panels during a transition. Prefer keyboard
  activation on a focused, observed tab/button when pointer geometry is moving;
  this is an interaction tactic, not a universal claim that clicks are broken.
- After Save/Close, confirm the old dialog has disappeared and the next owner is
  ready. Do not send the next section click into a moving replacement panel.
- For remote charts, distinguish source resolution busy from a completed empty
  operation catalog. Wait on authoritative readiness, not an unconditional sleep.
  Select the resource once, preserve compatible dimensions/metrics, and correct
  only the actual validated incompatibility after discovery completes.
- Prepare the allowed per-component snippets and reading-order map before the
  take; record a cumulative milestone after sources/KPIs, charts, remaining
  content, layout/connections and verification. Do not rediscover known failed
  List.config projections or chart ports during the timed run.

Keep installed capability separate from newer skill/source guidance. A newly
documented unified editor or cleanup fix is not available in an older host merely
because its skill was synchronized. Adopt only within the authorized scope and
report the version; comparable repetitions should retain a declared baseline.

## Finish and measure

Keep four KPI values on one desktop row when the reference does. Resolve bindings
before adjusting proportions. Measure borders/padding as well as minimum content
height; never inflate a card to conceal raw binding strings. Preview the child's
internal mobile layout as well as the canvas: stacking widgets alone does not
set internal direction. Check all cards, long chart labels, shell title wrapping,
legends, feed viewport and internal table scrolling.

Exercise chart selection to table queryContext, native clear, pagination, a read
detail and navigation. For example, the Hero HQ real incident counts were74→18
for CRITICA→74 after clear; these are observed counts, not future fixed fixtures.
Accessible chart data buttons can activate categories without brittle sector
coordinates. Take screenshots after scroll/animation has settled.

For timing, count insertion, individual content/shell editors, sources, every
connection, layout and verification. Keep normal waits in the total. If300s is
exceeded, finish the same-quality take and report the actual time; do not drop
widgets or omit validation to meet it. Report any pre-existing product limitation
separately from new regression or loss of fidelity in the take.

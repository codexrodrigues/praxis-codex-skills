# Choose Chart Data In A Page Builder Widget

Inspect the installed chart metadata/preset and open its content editor. Identify
the effective source among `chartDocument`, runtime `config`, local `data` and
composition inputs before changing presentation. Use the owner settings/runtime
skills for precedence; do not manufacture a document from a rendered chart.

1. Open the data/source section. For remote stats, use the governed resource
   selector when exposed. Allow resource resolution to finish, then select an
   offered operation, eligible dimension, metric and aggregation. Revalidate
   dependent selections when resource or operation changes.
2. Follow the catalog's operational path identity. A resource label, resourceKey
   and execution path can differ. If the current selection is rejected while a
   similarly named candidate is listed, record the identities/diagnostic before
   classifying a missing resource. Do not trial slash/prefix edits to bypass it.
3. Inspect effective-origin summary and validation. Distinguish catalog loading,
   denied/unavailable operations, missing fields and live-query failure. A listed
   resource proves discovery, not successful stats execution or permission.
4. Use native presentation controls and preview for the selected chart family.
   A synthetic preview proves layout only. Verify actual runtime data origin;
   sample rows or fallback numbers must not silently override remote results.
5. For point/selection/cross-filter behavior inspect existing source-event-specific
   composition targets. Establish a valid link in Page Builder first when required
   by the installed resolver, then configure the action offered for that event.
   Follow the composition skill for mapping and clearing; labels are not targets.
6. Apply/save through the owning panel, inspect settled chart values and reopen.
   Verify sample-data removal and query context preservation where required by
   the contract. Parent autosave can persist an Apply before the page Save action.

Use a new canonical insertion preset for new charts when the installed registry
offers one. For an existing runtime-only widget, keep migration/authoring support
explicit; render success does not prove its editor can reproduce that config.
Do not route the query through a state/config projection merely to defeat a
validator or leave an editor that shows a different effective chart on reopen.

Pair the chart with cards, forms or collections according to the job. Check long
labels, legend, accessible data, internal sizing and narrow layout. Before claiming
an interactive chart, exercise selection and native clear against the target and
confirm the result after acknowledged save/reopen.

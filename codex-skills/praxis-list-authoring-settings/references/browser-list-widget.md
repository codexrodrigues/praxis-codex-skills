# Configure List, Card And Tile Widgets

Use the installed preset and `PraxisListWidgetConfigEditor`. Insertion presets,
Content slot presets and runtime layout variants solve different decisions;
none proves data connectivity or interactions by itself.

1. Choose configuration origin deliberately. Page-owned composition normally
   uses the offered page strategy (`inputs.configPersistenceStrategy = 'input-first'`).
   Individual saved preferences can take precedence otherwise. The temporary
   preference option does not turn off parent-page persistence.
2. In Data identify the active source. `config.dataSource.resourcePath` and local
   `dataSource.data` are not interchangeable: retained local examples can govern
   results. Use discovery/contract evidence for a manual path field; do not
   promise that this wrapper includes a resource selector.
3. Resolve fields before mapping leading, primary, secondary, meta, trailing and
   features slots. Use native compact/operational presets and card/tile/list
   variants where suitable, then adjust the actual labels and supported tokens.
   Rendering cards does not change collection or event semantics.
4. Inspect `itemClick`, `actionClick` and `selectionChange` contracts before wiring
   a card as a filter or record selector. Project the actual event envelope into
   the target's public query/identity input; a displayed status or item title is
   not a filter key. Configure empty selection and clear without retaining the
   previous record. Use the Page Builder composition skill for the connection.
5. Configure structured actions, selection, rules and pagination only as needed.
   A rule's class/tone changes presentation; it does not enforce permission.

After Apply inspect settled results, slot values, count, selection and paging.
For advanced JSON inspect normalized output and persistence; accepting a property
does not prove runtime activity. Virtual-scroll or layout limitations belong to
the installed release and must be rechecked before reusing a historical workaround.
Use narrow runtime/editor checks and verify page and preference ownership on reopen.
